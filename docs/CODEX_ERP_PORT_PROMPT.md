## 0. What "done" means

The Django backend can do everything ERPNext's backend does for the in-scope modules, with results identical to real ERPNext v17: same doctypes and fields, same document lifecycle, same general-ledger and stock-ledger postings, same tax/rounding math, same reports, same permissions. "Looks similar" is a failure. Every claim of parity must be backed by a test or by a side-by-side comparison against the reference oracle (section 3).

Out of scope (do not port, do not stub): manufacturing, subcontracting (it needs BOM), HRMS (payroll, leave, attendance, expense claims), website/e-commerce/shopping cart, Frappe desk UI, integrations whose only purpose is a US/EU/other-country regional (Italy, Turkey, UAE, South Africa, USA, Australia). In scope: `accounts`, `stock`, `selling`, `buying`, `assets`, `projects`, `support`, `setup`, `utilities`, `maintenance`, `quality_management`, ERPNext-side `crm` (Opportunity, Prospect, Campaign, Contract, Appointment, Competitor, Lead is served by the existing Frappe CRM port), `controllers`, `regional` (Kenya only, section 8), `telephony`, `communication`, `bulk_transaction`, `edi`, `erpnext_integrations` (Plaid and bank pieces that accounts needs), `portal` (portal user pieces that Customer/Supplier need).

## 5. Architecture to implement

### 5.1 Apps and import paths
- Create two Django apps: `apps/frappe` (framework runtime semantics) and `apps/erpnext` (ported ERPNext). `apps/erpnext` has sub-packages mirroring ERPNext modules: `accounts`, `stock`, `selling`, `buying`, `setup`, `assets`, `projects`, `support`, `maintenance`, `quality_management`, `crm`, `utilities`, `controllers`, `regional`, `telephony`, `communication`, `portal`, `bulk_transaction`, `edi`, `erpnext_integrations`. Inside each: `doctype/<doctype_name>/`, `report/<report_name>/`, plus the module's plain `.py` files (`general_ledger.py`, `utils.py`, `party.py`, ...).
- Insert `backend/apps` into `sys.path` in settings so ported code keeps ERPNext's original imports (`import frappe`, `from erpnext.accounts.utils import ...`, `frappe.get_attr("erpnext....")`). Register `frappe` and `erpnext` in `INSTALLED_APPS` with AppConfigs. Do not shadow Django or third-party packages. Verify no import cycles at startup.

### 5.2 Storage (match Frappe exactly so ported SQL works)
- One Django model per doctype and per child doctype. `db_table = "tab<DocType Name>"` including spaces (e.g. `"tabSales Invoice"`, `"tabSales Invoice Item"`).
- Primary key: `name` varchar(140). Standard columns on all: `owner`, `creation`, `modified`, `modified_by`, `docstatus` (smallint), `idx` (int). Child tables add `parent`, `parentfield`, `parenttype` (varchar 140) and index on `parent`. Tree doctypes add `lft`, `rgt` (int), `old_parent`. Submittable doctypes add `amended_from`.
- Column per fieldname with these types: Data/Select/Link/Dynamic Link/Autocomplete/Color/Barcode/Read Only (varchar, length 140 or the field's `length`); Small Text/Text/Long Text/Text Editor/Code/JSON/HTML Editor/Markdown Editor/Password/Attach/Attach Image/Signature/Geolocation (text); Currency/Float/Percent/Duration (numeric(21,9)); Int (integer; Long Int bigint); Check (smallint 0/1, **not boolean**); Date/Datetime/Time native. No column for Section Break, Column Break, Tab Break, HTML, Button, Heading, Image, Table, Table MultiSelect (Table MultiSelect stores child rows in its child table).
- **Links are plain varchar columns, no foreign keys**, validated in Python. Honour `search_index`, `unique`, `not_nullable`, `default` (literal defaults go on the column; dynamic defaults like `Today`, `__user`, `:Company` are applied in Python on new docs). `reqd` is enforced in Python, not by NOT NULL (Frappe stores NULL/empty permissively).
- Single doctypes (`issingle`): values in a `tabSingles(doctype, field, value)` table, same API as normal docs.
- Naming counters in `tabSeries(name, current)`; use `SELECT ... FOR UPDATE` semantics so concurrent inserts never repeat a name.
- Every table is created through Django migrations generated by `makemigrations` (never hand-edited unless justified in the report). `makemigrations --check --dry-run` must be clean at the end of every block.

## 8. Style and quality bar
- Python 3.13, type hints where the source has them; ports keep the source's shapes. Format with the project's existing style (black-like, 120 cols if configured; check `backend/pyproject.toml`/`setup.cfg`).
- No comments, no commented-out code, no TODO markers. Unfinished work goes in the status ledger, not in code.
- No broad `except:`; propagate Frappe-style exceptions; never swallow ledger errors.
- No N+1 in list endpoints; use `select_related`/`prefetch_related` or raw SQL like the source does.
- Money and quantities use `Decimal` internally where the source uses `flt` with precision; replicate `flt` semantics exactly (floating point as in Frappe, rounding through `rounded`), because parity with the oracle depends on identical arithmetic, including `flt(value, precision)` call sites. Do not "improve" by switching to Decimal if it changes results.
- Everything a reviewer needs is under `backend/` and `docs/`; tests under `backend/apps/erpnext/tests/` and `backend/apps/frappe/tests/` (module-per-doctype naming `test_<doctype>.py`, port upstream `test_*.py` cases next to each controller wherever they apply).

## 10. Things that commonly go wrong (read before you start)
- PostgreSQL strictness: `GROUP BY` must include selected non-aggregates; Check columns are smallint so `= 1` works but `= true` does not; `ifnull(x, '')` -> `coalesce(x, '')`; mixed-case identifiers need quotes (`"tabSales Invoice"."posting_date"`); `LIMIT ... OFFSET` order; `lower()`/`ilike` for case-insensitive search (Frappe on MariaDB is case-insensitive by default, Postgres is not, so port `like` conditions with `ilike`); date arithmetic via `interval`; `DISTINCT` with `ORDER BY` needs the order columns in select.
- Frappe's `flt`/`cint` accept `None`, `""`, formatted numbers and locale formats; replicate exactly.
- Child table `idx` and `parent` handling on submit/cancel/update-after-submit; per-row `docstatus` follows parent.
- Cancel of a submitted document must keep the document row and set `docstatus=2`; GL entries are reversed or deleted per `Accounts Settings.delete_linked_ledger_entries` in v17, port the exact rule.
- Exchange-rate lookups hit the network; wrap behind an injectable client and cache; tests stub it.
- Naming series with company abbreviation tokens and `amended_from` suffixes.
- Do not let doctype names containing spaces break Django model class names; use CamelCase class names (`SalesInvoice`) and keep `db_table` and meta `doctype` equal to the original name.
- Date/time: Frappe stores naive local datetimes in the site time zone; keep a single documented convention (naive, `Africa/Nairobi`) and apply it everywhere; do not mix aware/naive.
- `frappe.flags` and request-scoped state must be isolated per request/thread (contextvars), not module globals, otherwise parallel requests leak flags like `ignore_permissions`.
