## Blocking defects (verified by reading the code and running it)

1. **Controllers are empty stubs.** `fiscal_year.py`, `cost_center.py`, `item_group.py` (and the rest) contain only `class X(Document): doctype = "..."`. The vendor controllers are 139, 152 and 132 lines of real logic (validation of dates and overlaps, `auto_create_fiscal_year`, `get_from_to_dates`, `validate_dates`, `on_update` hooks, tree rules, naming, `check_if_child_exists`, etc.). The brief required the pilot controllers ported verbatim. Port every method of every pilot controller, keeping names, arguments, control flow and `_()` messages.
2. **Rounding is wrong, which breaks ledger parity.** `flt(2.675, 2)` returns `2.67` and `flt(1.005, 2)` returns `1.0`; ERPNext returns `2.68` and `1.01`. `flt` must be ported from `vendor/frappe/frappe/utils/data.py` (Decimal-based, ROUND_HALF_UP via the string form, `rounding_method` from System Settings, locale number formats, `precision` argument semantics). `data.py` is 83 lines and covers a small fraction of the upstream file. Port the whole module faithfully, including `money_in_words`, `fmt_money`, `get_first_day`, `get_last_day`, `get_quarter_start`, `get_year_ending`, `formatdate`, `get_time`, `comma_and`, `cast`, `evaluate_filters` and the rest. Then port the upstream tests (`vendor/frappe/frappe/tests/test_utils.py`, `test_data.py`) and make them pass.
3. **Permissions are a security hole.** `has_permission` ends with `return ptype == "read"`, so any user can read every doctype whether or not a role matches. It also swallows all errors with `except Exception: pass` and hardcodes roles. Implement the real matrix (role, permlevel, read/write/create/delete/submit/cancel/amend, `if_owner`, user permissions, doc shares), default-deny, no silent exception swallowing, and wire it into every API call. `flags.ignore_permissions` is currently set and never checked.
4. **No child tables.** `Document.append` just appends a dict to a Python list; `db_insert`/`db_update` ignore it, so child rows (for example Fiscal Year `companies`, UOM conversion factors) are never loaded, validated or saved. The generator also omits Table fields from the model. Implement child-table load/save/delete with `parent`, `parentfield`, `parenttype`, `idx` handling, `append()` returning a row object, `Table MultiSelect`, and per-row validation messages ("Row #n: ...").
5. **Lifecycle order and rules differ from Frappe.** `insert()` runs `validate` before naming and `before_insert` after validation; Frappe runs `before_insert`, then naming, then `before_validate`/`validate`/`before_save`. Also missing: modified-timestamp conflict check, `docstatus` transition rules (0->2 forbidden, `update_after_submit` for `allow_on_submit` fields, `on_update_after_submit`), `amended_from` and amend naming, `set_only_once`, `non_negative`, `min/max_value`, defaults including dynamic ones (`Today`, `__user`), `fetch_from`/`fetch_if_empty`, precision rounding of floats/currency on save, `db_set`, `get_doc_before_save`, `has_value_changed`, `copy_doc`, `doc_events` dispatch from ERPNext's `hooks.py`, and `reload()`. Port `vendor/frappe/frappe/model/document.py` and `base_document.py` method by method.
6. **Exceptions and error contract.** Everything raises bare `Exception`, and the REST layer converts every exception to a 400. Port Frappe's exception classes (`ValidationError`, `MandatoryError`, `LinkValidationError`, `DuplicateEntryError`, `DoesNotExistError`, `PermissionError`, `CannotChangeConstantError`, ...) with their HTTP mapping (417/403/404/409) and Frappe's JSON error shape (`exc_type`, `_server_messages`) so the future UI can behave like Frappe's. Error text must match Frappe's.
7. **Naming is a placeholder.** `make_autoname` only handles a prefix plus `#` run. It does not parse ERPNext's real patterns (`ACC-SINV-.YYYY.-.#####`, `.MM.`, `.DD.`, `.abbr.`, `{field}` tokens in `format:`), does not support the `naming_series` field and per-company series, `Prompt`, `autoincrement`, `revert_series_if_last`, or collision handling; `hash` is not Frappe's hash. Port `vendor/frappe/frappe/model/naming.py` (`parse_naming_series`, `make_autoname`, `set_name_by_naming_series`, `getseries`, `set_name_from_naming_options`, `validate_name`, `append_number_if_name_exists`). Add the concurrent two-thread test required by the brief.
8. **NestedSet is a full-table rebuild on every save**, with N+1 queries, no `old_parent`, no `is_group` rules, and a loop check that only catches self-parenting. Port `vendor/frappe/frappe/utils/nestedset.py` (`update_nsm`, `update_add_node`, `update_move_node`, `validate_loop`, `remove_subtree`, `rebuild_tree`, `get_ancestors_of`, `get_descendants_of`, `get_root_of`) and add the 200-random-operations consistency test.
9. **The REST API is CRUD only.** Missing: list with Frappe filter syntax (`filters`, `or_filters`, `fields`, `order_by`, `group_by`, paging, `pluck`), DELETE, rename, link search, `get_value`/`set_value`, run whitelisted document methods, tree endpoints (`get_children`, `add_node`), `get_doc_permissions`, `docinfo`, `onload`, `make_mapped_doc`. The brief's section 5.5 lists the contract. The current `_guard` also turns every error into HTTP 400.
10. **Tests are not tests.** `manage.py test` cannot run because `bbs_erp` cannot create a test database, and the substitute `verify_erpnext_foundation` command writes to the dev database. Pytest/Django tests must run in an isolated database. Ask the project owner to run once with a PostgreSQL superuser: `ALTER ROLE bbs_erp CREATEDB;` (or a documented alternative such as a test schema), then run the real test suite. Do not mark rows "tested" in `ERP_PORT_STATUS.md` until `manage.py test` actually runs them and they pass. Several rows are mislabeled: hand-written files are marked "generated", and `document.py` is marked "tested" on the basis of a smoke command.
11. **Frappe core doctypes were not generated** (Workflow, Custom Field, Property Setter, Version, Number Card, Dashboard, Report, Print Format, Letter Head, Notification, Country, Language, Module Def, etc.) and there is no role/DocPerm data model beyond four tables. Required by the brief for Block 1.
